# HUS — Integration Guide

HUS is a language-agnostic biometric uniqueness system. Integrate via **REST API** (any language), **Rust SDK**, or **C FFI** (Python/Go/Java).

## Stop — Read This First

**Never deploy `.env` files to production servers.** The gateway reads configuration from environment variables (`HUS_*`), not `.env` files. Set them via your deployment platform (Docker, K8s, systemd, etc.):

```bash
# Good: env vars on the platform (Docker, K8s, systemd)
docker run -e HUS_REGISTRY=0x... -e HUS_PUBLIC_KEY=0x... hus-gateway

# Bad: shipping a .env file to the server
scp .env prod-server:/app/   # ← DO NOT DO THIS
```

## What you need

| Item | Detail |
|------|--------|
| Network | Shellnet GraphQL endpoint (provided) |
| Registry address | HusRegistry contract address (provided) |
| Proving/verifying keys | Generated by HUS team (~17MB PK, ~1KB VK) |
| Protocol wallet | Keypair for signing blockchain txs (provided) |
| Gas (VMSHELL) | Pre-deposited for your app |

## Integration paths

| Path | Use when… | Effort |
|------|-----------|--------|
| **REST API** | Any language (curl, Python, JS, Go, Java) | ~10 min |
| **Rust SDK** | You write Rust | ~15 min |
| **C FFI** | Python, Go, C++, Swift, Kotlin (native) | ~20 min |

## Path 1 — REST API (any language)

Run the gateway:

```bash
# Via CLI args
cargo run -p hus-gateway -- \
  --network https://shellnet.ackinacki.org/graphql \
  --registry 0:<address> \
  --proving-key-file /path/to/pk.bin \
  --verifying-key-file /path/to/vk.bin \
  --public-key 0x<wallet-pub> \
  --secret-key 0x<wallet-secret> \
  --attest-policy /path/to/attest-policy.json

# Or via env vars (preferred for production)
export HUS_NETWORK=https://shellnet.ackinacki.org/graphql
export HUS_REGISTRY=0:<address>
export HUS_PUBLIC_KEY=0x<wallet-pub>
export HUS_SECRET_KEY=0x<wallet-secret>
export HUS_ATTEST_POLICY=/path/to/attest-policy.json   # required, docs/attestation.md
cargo run -p hus-gateway
```

Once running, call from any language:

```bash
# 1. Register your app (one-time)
curl -X POST http://localhost:3000/api/v1/register-app \
  -H 'Content-Type: application/json' \
  -d '{"app_name":"my-app","modality_ids":[0,4]}'

# 2. Project embedding → obfuscated vector
curl -X POST http://localhost:3000/api/v1/project \
  -H 'Content-Type: application/json' \
  -d '{"seed":"abab...ab","embedding":[0.1,0.2,...],"proj_dim":128}'

# 3. Generate Groth16 proof
curl -X POST http://localhost:3000/api/v1/prove \
  -H 'Content-Type: application/json' \
  -d '{"v_obf":[0.05,-0.12,...]}'

# 4. Verify proof off-chain (required before submission)
curl -X POST http://localhost:3000/api/v1/verify \
  -H 'Content-Type: application/json' \
  -d '{"proof":"hex...","commitment":"hex...","v_obf":[0.05,-0.12,...]}'
```

**Full API reference:** `docs/api-gateway.md`

### Python

```python
import requests

HUS = "http://localhost:3000/api/v1"
seed = "abababababababababababababababab" * 2  # 64-char hex

r = requests.post(f"{HUS}/project", json={
    "seed": seed, "embedding": [0.1]*40, "proj_dim": 128
})
v_obf = r.json()["v_obf"]

r = requests.post(f"{HUS}/prove", json={"v_obf": v_obf})
proof, comm = r.json()["proof"], r.json()["commitment"]

r = requests.post(f"{HUS}/verify", json={
    "proof": proof, "commitment": comm, "v_obf": v_obf
})
assert r.json()["valid"] is True
```

### JavaScript

```javascript
const HUS = "http://localhost:3000/api/v1";

const { v_obf } = await (await fetch(`${HUS}/project`, {
  method: "POST",
  body: JSON.stringify({ seed, embedding, proj_dim: 128 }),
  headers: { "Content-Type": "application/json" },
})).json();

const { proof, commitment } = await (await fetch(`${HUS}/prove`, {
  method: "POST",
  body: JSON.stringify({ v_obf }),
  headers: { "Content-Type": "application/json" },
})).json();
```

### Go

```go
package main

import (
    "bytes"
    "encoding/json"
    "net/http"
)

type ProveResult struct {
    Proof      string `json:"proof"`
    Commitment string `json:"commitment"`
}

func main() {
    body, _ := json.Marshal(map[string]any{"v_obf": []float64{0.05, -0.12}})
    resp, _ := http.Post("http://localhost:3000/api/v1/prove",
        "application/json", bytes.NewReader(body))
    var result ProveResult
    json.NewDecoder(resp.Body).Decode(&result)
}
```

### curl (shell scripts)

```bash
seed=$(printf 'ab%.0s' {1..32})  # 64-char hex

v_obf=$(curl -s -X POST http://localhost:3000/api/v1/project \
  -H 'Content-Type: application/json' \
  -d "{\"seed\":\"$seed\",\"embedding\":[0.1]*40,\"proj_dim\":128}" \
  | jq -r '.v_obf')

proof_resp=$(curl -s -X POST http://localhost:3000/api/v1/prove \
  -H 'Content-Type: application/json' \
  -d "{\"v_obf\":$v_obf}")
proof=$(echo "$proof_resp" | jq -r '.proof')
commitment=$(echo "$proof_resp" | jq -r '.commitment')
```

## Path 3 — C FFI (Python, Go, Swift, Kotlin)

Build the shared library:

```bash
cargo build -p hus-sdk --release --features ffi
# → target/release/libhus_sdk.so (Linux)
# → target/release/libhus_sdk.dylib (macOS)
# → target/release/hus_sdk.dll (Windows)
```

### Python (ctypes)


## On-Chain flow (working path)

Due to the `gosh.vergrth16` opcode limitation (hardcoded ZkLogin VKs), proofs are verified **off-chain** before submission. On-chain stores only commitment hashes:

```
Device capture → Extract → BioHashing project → Groth16 prove
                                                    │
                                          ┌─────────┴──────────┐
                                          │ Verify off-chain   │ ← REST /api/v1/verify or SDK
                                          │ (arkworks BN254)   │
                                          └─────────┬──────────┘
                                                    │ valid
                                          ┌─────────┴──────────┐
                                          │ submitCommitment() │ ← REST /api/v1/submit or Rust SDK
                                          │ (commitment+v_obf) │
                                          └─────────┬──────────┘
                                                    │
                                          On-chain L2 distance check → isUnique? ✓/✗
```

## `.env` Best Practices

| Do | Don't |
|----|-------|
| Set `HUS_*` vars in Dockerfile/K8s manifest | Commit `.env` to git |
| Use a secrets manager (Vault, AWS Secrets Manager) | `scp .env` to production |
| Rotate secrets if `.env` was ever committed | Hardcode secrets in source |
| Add `.env` to `.gitignore` immediately | Share `.env` between dev and prod |

For local dev, copy `.env.example → .env` and fill in values. It is already gitignored.
